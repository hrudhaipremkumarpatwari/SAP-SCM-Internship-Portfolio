# Week 3 Submission Description

This report presents a controlled data-migration and integration-testing strategy for the same hypothetical Horizon Foods ERP learning case. It defines a deliberately small, spreadsheet-based sample scope: five material-master rows, four unique accepted material records, one quarantined duplicate, and four opening inventory balances. The materials and quantities continue the Week 2 design assumptions: RM-CHILI at 120 KG, RM-OIL at 80 L, PKG-POUCH at 2,500 EA, and FG-CHUTNEY at 400 CASE. These are invented training values and were not taken from a company system or loaded into a live ERP.

The strategy covers source profiling, cleansing, source-to-target mapping, unit-of-measure crosswalks, prerequisite master data, staging, repeated validation, mock loading, reconciliation, and business-owner sign-off. A separate five-row legacy extract makes the source count and duplicate decision reviewable. A mapping register specifies sample legacy fields, target business meanings, transformations, bilingual HSK 4 field cues, validation rules, and dispositions. It explains why an unknown unit must be blocked pending data-owner approval and why a duplicate key must be quarantined instead of overwritten. The inventory reconciliation file shows source and mock-target balances by material and unit, with zero variance on all four accepted rows; unlike units are never added together. A labeled static exception mock-up summarizes the simulated batch; it is not a SAP screen.

The integration-test register contains ten end-to-end cases spanning purchase-order processing, receipt, master-data validation, MRP/BOM planning, production order release, component issue, finished-goods receipt, balance reconciliation, and role controls. Two seeded exceptions fail in the first mock cycle, then pass after the described corrections; all ten pass in the final simulated retest. The document states the formulas for acceptance, reconciliation, pass rate and defect closure, while explaining that this small designed sample does not prove production readiness. It includes contingency controls for changed extracts, missing prerequisites and rollback, as well as Chinese labels paired with stable English identifiers and a bilingual-review requirement. No live SAP migration, integration test or production result is claimed.
